# DeshSubDispatch — Project Audit (2026-10-18)

Method: read every file in `src/`, `tests/`, docs and CI; ran `tsc --noEmit`, `npm test`,
`npm run build` (all green); started the built bundle in HTTP mode and exercised
`/health`, `/`, MCP `initialize` → `tools/list`, `register_agent`, `dispatch_task`,
`get_task_result(wait)`, a fresh second session's `list_agents`, `get_skill` on a missing id,
`dispatch_task` with an unknown agent, `prompts/list`, `resources/list`.

## Scores

### SPEC — 7/10
The README promises are mostly real: hybrid llm/process/http agents, priority+DAG
orchestration, retries/timeouts/cancellation, skills presets, 16 tools, stdio+HTTP+SSE
routes, self-contained bundle, env-var docs matching the code.

Gaps, highest value first:
1. **Prompts capability advertised but not implemented** — `capabilities.prompts` is declared,
   `prompts/list` returns `-32601 Method not found` (exercised). A client that selects this
   server for prompts is broken on first call.
2. **SSE legacy transport claims** exist in code but were never exercised this pass; no test
   covers `/sse` + `/messages` (unproven, `tests/dispatcher.test.ts` only covers 2 dispatcher flows).
3. **"Full orchestration" is only proven for the happy path** — no test exercises retry,
   cancel-during-run, dependency-failure propagation, or per-agent concurrency limits.

### DESIGN — 6/10
Real separation exists (agents/dispatcher/skills/persistence/tools), but ownership of the
central state object is wrong in two places:

1. **`src/index.ts`** creates a whole new `createServer()` + new SQLite connection **per MCP
   session** in HTTP mode — nobody owns "the" dispatcher; sessions hold diverging in-memory
   registry/task snapshots and never close their DB handles. (Also: `--both` = two divergent
   dispatchers.)
2. **`src/server.ts`** and `src/dispatcher/dispatcher.ts` disagree on the same contract:
   tests call `createServer({ dbPath: ":memory:" })`, `createServer` accepts only
   `{ maxConcurrency }` and silently drops `dbPath`, so **tests write into the real
   `./desh-sub-dispatch.db`** (confirmed: old `cat` agent rows from test runs are served to
   fresh sessions). Two sources of truth for one configuration value.
3. **`src/tools/register.ts`** reaches into private state: `(dispatcher as any).maxConcurrency`,
   `(dispatcher as any).active` — stats have no owner on the Dispatcher.
4. **`src/dispatcher/executor.ts`** mixes three provider protocols, the OpenAI tool-calling loop
   and builtin tool execution (`run_shell`, `http_get`) in one 250-line file; `Dispatcher.db` is `any`.

### CORRECTNESS — 6/10
Exercised and working: health, homepage (200 text/html), initialize/session handshake,
`tools/list` (16 tools), register → dispatch → wait-for-result (`succeeded`, attempts=1),
`resources/list`, cross-session agent *reload* from SQLite, build/tests/tsc green.
Defects found by exercising:
1. **Silent async failure**: `dispatch_task` with an unknown `agentId` returns
   `{"status":"pending"}` happily; the task only fails later in `tick()`. No actionable error.
2. **`prompts/list` → -32601** (see SPEC #1).
3. **Test DB pollution** (see DESIGN #2) — behaviorally confirmed via stale rows in the dev DB.
4. AssertionError risk unexercised: cross-session *write* visibility (session B seeing an agent
   registered after B's construction) is **asserted but not proven** this pass — capped at 6.
5. `get_skill` missing id returns bare `"not found"` — is an error, but gives the agent nothing
   actionable.

### QUALITY — 5/10
Against the smallest version of the same behavior:
1. `src/tools/register.ts` repeats the same `JSON.stringify`-into-`content` wrapper 16×, every
   callback param typed `any`, response shapes inconsistent (`taskId` vs `id`, bare arrays vs
   objects) — a response helper + typed args would cut ~40% of the file.
2. **Build artifacts committed**: whole `dist/` incl. `.map` files and a stale
   `dist/server.bundle.js` next to `server.bundle.cjs` (4.1 MB tracked).
3. Task lifecycle double-writes: `pending→queued→running` with a full SQLite upsert per hop and
   `store.list()` rescanned every `tick()`; `runAt` field is dead (never set).
4. Both READMEs repeat the same 10× near-identical JSON config blocks (one host table would do).

## Out of scope for this pass (report only)
- Security of the public no-auth endpoint: anonymous `register_agent` with `kind:"process"` is
  remote command execution; `metadata.webhookUrl` is SSRF; `enableTools` LLM agents expose a
  builtin `run_shell`; rate limiting is off by default. Should be the next hardening pass.
- SSE transport tests, `.gitignore` for `dist/`.

## Single most valuable next pass
Implement the mcp-builder effectiveness plan (prompts, tool metadata/schemas/annotations,
actionable errors, list pagination, single shared dispatcher, test isolation) — it closes the
only two *protocol-visible* broken promises (prompts, error quality) and the two ownership bugs
that make everything else hard to trust.
